# Domain docs

Port Hopper uses a single domain context across its npm workspaces.

- Before exploring, read the root `GLOSSARY.md` and any relevant ADRs in
  `docs/adr/`.
- If those files are absent, continue. Create them through domain modeling
  when terms or decisions are settled.
- Use glossary terms in issues, proposals, and tests. Flag missing terms for
  domain modeling.
- Call out conflicts with existing ADRs explicitly.
